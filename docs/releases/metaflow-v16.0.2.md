# Zotero MetaFlow 16.0.2

## 缓存与操作记录

- 将 API 成功响应与操作记录集中保存到 Zotero 配置目录的 `zotero-metaflow-cache` 文件夹。新缓存从空状态开始；不读取、迁移或删除旧版散落文件。
- 核心流程按阶段写入开始和完成检查点；重启后将未结束阶段标记为中断，区分失败、准备失败和取消，并保持写入失败后的操作编号连续。
- 启动时及每 10 分钟清理过期缓存。并发维护合并执行，关闭时等待在途写入，写入失败可通过后续维护重试。
- 设置页显示实际缓存路径、API 索引数量、操作记录数量与磁盘占用（包含备份和临时文件），提供打开目录、刷新占用和清理过期数据入口。
- API 主文件维持 8 MiB / 1,024 条索引上限；有效操作记录维持 30 天 / 200 次 / 2 MiB 上限，备份另计。定期清理主文件中的过期历史；写入和恢复备份时同样过滤过期记录。
- 操作记录仅保存摘要、字段名、原因码和本地条目标识，不保存题名、字段原文、PDF 正文、密钥或原始错误文本。

## 发布构建

- 固定构建时间、ZIP 条目时间戳与文件顺序，生成可重复的 XPI；同步维护更新源 SHA-512 和交付 SHA-256。
- 新增 13 项架构及版本守卫，检查中英文本、版本、宿主声明、源码边界和打包完整性。

- 修正 npm 执行原生测试时的参数转发，确保 `--no-watch` 生效；连接测试按真实输入事件保存配置。
- 期刊列、菜单和工作流测试使用独立配置执行，检查所有测试文件被完整覆盖；单一共享配置的运行方式保留用于排查跨场景状态依赖。

兼容声明为 Zotero 10.0–12.*；实际宿主验证范围以发布验证记录为准。
