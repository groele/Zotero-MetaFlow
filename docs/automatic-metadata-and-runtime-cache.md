# 自动元数据填充与本地运行数据

适用于正式版 `16.0.3`。

## 元数据按判据直接填充

两个核心命令及高级元数据核验不再打开字段选择、标识符选择或冲突确认窗口，也不显示元数据审阅面板。

1. 使用已有 DOI、arXiv、PMID、PMCID 或 ISBN。同类标识符有不同候选时直接跳过，等价 ISBN-10/ISBN-13 视为同一版本。PDF 线索不按出现顺序自动选取。
2. 外部响应须通过现有标识符核验。标题、年份或首位作者存在身份冲突时保留原条目，记录跳过原因，不弹出确认界面。
3. 标题检索与 PDF 线索还须同时满足标题一致，且已有年份或首位作者至少有一项独立一致。
4. “检查并修复元数据”默认只填空字段；“更新元数据”遵循保存的补空／覆盖模式。作者修复开关开启时，经身份核验后可补全非空但不完整的作者名单；关闭时不改作者。
5. 写入前再次检查原条目快照。检索期间发生手工编辑时拒绝过期响应；取消会停止后续阶段。
6. 启用 arXiv 正式版查询后，经过核验的正式版自动建立或复用关联，保留预印本；默认自动流程不把预印本改成期刊论文。

批量去重继续使用重复组选择，与元数据自动填充相互独立。

## 分层缓存默认值

| 数据 | 有效期／失效规则 | 数量与容量 | 依据 |
| --- | --- | --- | --- |
| 公共检索响应 | 5 分钟 | 128 条已完成响应，正文预算 4 MiB | 短时间连续操作共享请求，版本查询及时更新 |
| EasyScholar 评级响应 | 72 小时 | 与其他认证接口共享下述预算 | 评级相对稳定，减少同刊重复请求 |
| Semantic Scholar 响应 | 24 小时 | 认证响应内存 512 条，正文预算 16 MiB | 保持论文信息适度新鲜，并支持跨会话复用 |
| 成功但为空的评级响应 | 5 分钟 | 共用接口缓存预算 | 避免空结果长期遮蔽新增数据 |
| 持久接口缓存 | 保留原响应到期时间 | 1,024 条（含标识符别名），主文件 8 MiB；单条最多 512 KiB | 数量和字节双重限制，超大响应正常返回但不缓存 |
| 已解析评级对象 | 同源截止时间，最长 72 小时；空结果最长 5 分钟 | 256 条 | 复用解析结果，避免重复解析响应 |
| 本地去重搜索 | 文库增删改、移入回收站或刷新立即失效 | 16 个文库 | 本地变更优先于固定时间周期 |
| 内置数据库及索引 | 随插件版本或显式重载更新 | 有限的内置资源 | 不重复读取、解析相同静态文件 |
| 自定义文件 | 每批后清除相关缓存，重新校验后使用 | 按已配置文件 | 同一路径修改也能生效 |
| 已保存期刊资料索引 | 作为本地历史资料保留，不充当未过期接口响应 | 20,000 个索引键 | 支持离线使用，保留已有资料来源标记 |
| 运行历史文件 | 最近 30 天 | 200 批次，主文件 2 MiB | 限制长期磁盘占用并支持追溯 |

进行中的共享请求不因缓存淘汰而取消；容量限制优先淘汰已完成的响应。上述内存字节预算统计响应正文，不等于整个 JavaScript 堆的总内存上限。

缓存命中不会延长原到期时间，不触发重复写盘。内存与持久缓存采用最近访问顺序淘汰；读取优先使用内存，每个会话只载入一次持久缓存。相同请求合并执行，单个订阅者取消不取消其他订阅者。错误响应不作为有效结果缓存。

旧接口缓存迁移到格式版本 3。旧版 72 小时论文缓存会收紧到 24 小时；迁移与别名读取均不会延长原截止时间。遇到未来格式版本时保留原文件，不由旧客户端覆盖。

## 专用缓存目录和操作记录

所有新增持久缓存位于当前 Zotero 配置目录的 `zotero-metaflow-cache/` 文件夹（或在设置页自定义的缓存目录）。`api-cache.json` 保存去重后的成功服务响应，`operation-history.json` 及 `.bak` 保存操作记录。设置页显示实际目录路径，可直接打开该文件夹或自定义文件夹；“打开本地运行记录”仍可直接打开记录文件。旧版本遗留在配置目录根部的缓存文件不迁移、不读取、不删除，新目录从空缓存开始。

记录批次时间、规则、成功／失败／取消计数、耗时、条目所属库及稳定键、修改字段名和原因代码。核心流程在每个阶段开始前和完成后写入检查点，因此意外退出后，重启读取记录时会把仍处于运行状态的批次与阶段标记为中断；普通规则批次在完成时写入摘要。每个批次最多保留 50 个条目摘要；超出时标记 `truncated`，批次总计数完整保留。不会写入 API 密钥、完整请求地址、PDF 正文、题名、完整错误文本或字段修改前后的原始内容。元数据本身继续由 Zotero 数据库保存。

普通运行记录在内存中聚合，500 毫秒合并落盘；核心流程阶段检查点在边界处立即落盘，同一修订的并发刷新合并为一次写入。正常关闭插件时再刷新，并在 Gecko 的配置目录关闭阶段注册异步写入屏障，等待待写数据完成。使用临时文件替换主文件，保留上一份有效快照 `.bak`。主文件损坏时恢复有效备份；运行期间主文件被外部破坏也不会污染内存中的有效备份快照。清理历史会同时清理主文件与备份，防止已清除记录重新出现。

写入失败保留已有有效文件并允许重试，不影响已经保存的文献。异常退出最多会丢失当前未成功写入的阶段边界；已落盘检查点能指出最后完成或中断的阶段。此文件用于运行追溯，不承担文库恢复。

高级接口为 `Zotero.MetaRef.api.runtimeData.path()`、`cacheDirectory()`、`read()`、`flush()`、`clear()`；清理只影响本地运行记录。

## 验证范围

新增纯逻辑与真实文件测试覆盖自动判据、缓存期限、旧格式截止时间迁移、容量约束、重复写入抑制、并发请求复用、损坏恢复、写入失败重试、未来格式保护和历史清理。最终计数及双宿主实机结果见交付目录的验证记录。在线服务使用受控响应，不代表全部真实账户权限或超大文库长期压力验证。

## 定期维护和占用展示（16.0.2）

启动后和每 10 分钟执行一次过期清理，关闭插件或进入配置目录关闭屏障时先停止定时器，并等待已有维护写入结束。并发的维护操作合并为同一次执行；写入失败保留待写修订，下一次定期维护或手动清理会重试。

设置页展示 API 索引数量、有效操作记录数和实际磁盘文件占用（包括备份及在途临时文件），提供“刷新占用情况”和“清理过期缓存”。维护仅处理本插件已知的文件，不扫描文献附件，也不删除文件夹中的其他文件。未来格式受保护时显示提示。

即使没有新任务，定期维护也会剔除主文件中的过期记录；写入主文件时同时过滤备份快照。恢复备份时始终按 30 天期限过滤，过期记录不会恢复为有效历史。备份文件是上一份有效快照，其物理内容可能在下一次主文件写入前超过 30 天。阶段状态区分完成、失败、取消与中断；准备失败同样记作失败，避免操作记录误报成功。
